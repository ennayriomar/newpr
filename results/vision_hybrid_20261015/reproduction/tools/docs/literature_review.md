# Phase A literature and source verification

This review supports designing a new hybrid for reliable industrial anomaly localization. It does not establish novelty, reproduce a published benchmark, implement a new detector, or demonstrate improved accuracy. The inspected project currently uses a frozen pretrained DINOv2 ViT-B/14 backbone at 224 pixels; results from papers using other backbones, resolutions, augmentations, and support protocols cannot be transferred to that implementation.

Verification evidence is recorded in `source_verification.json` in the Phase A evidence directory, with actual HTTP response metadata, retrieved page titles and citation metadata, response hashes, current upstream Git metadata, pinned source URLs, and bounded search results. Upstream source text is inspected but not copied into that JSON. Phase A audit date is 2026-10-14 in the user's Asia/Shanghai context; exact retrieval timestamps are recorded in UTC in the evidence JSON. No new experiments were run for this review.

## SubspaceAD: paper, source, and reproducible recipe

The authoritative paper is [SubspaceAD: Training-Free Few-Shot Anomaly Detection via Subspace Modeling](https://openaccess.thecvf.com/content/CVPR2026/html/Lendering_SubspaceAD_Training-Free_Few-Shot_Anomaly_Detection_via_Subspace_Modeling_CVPR_2026_paper.html), CVPR2026. Its actual publisher page describes frozen DINOv2 patch features, a normal PCA subspace, and reconstruction-residual anomaly scores. The official repository is [CLendering/SubspaceAD](https://github.com/CLendering/SubspaceAD).

Both the project cache and current upstream HEAD were independently checked. They are the same commit, [`ef56d5c8ab2f1feb7dda1c93b25cc3f73f0960d7`](https://github.com/CLendering/SubspaceAD/commit/ef56d5c8ab2f1feb7dda1c93b25cc3f73f0960d7). The upstream license API identifies Apache-2.0 and a [LICENSE file](https://github.com/CLendering/SubspaceAD/blob/ef56d5c8ab2f1feb7dda1c93b25cc3f73f0960d7/LICENSE).

The following is the pinned repository's few-shot benchmark-script recipe, not a claim of having reproduced its published results:

| Item | Verified setting and source |
|---|---|
| Backbone and resolution | `facebook/dinov2-with-registers-giant`, 672 pixels, in [benchmark_few_shot.sh](https://github.com/CLendering/SubspaceAD/blob/ef56d5c8ab2f1feb7dda1c93b25cc3f73f0960d7/scripts/benchmark_few_shot.sh). |
| Features | Arithmetic mean of Hugging Face hidden states indexed `-12,-13,-14,-15,-16,-17,-18`; CLS/register tokens are discarded. These are hidden-state indices, not the project's zero-based ViT-B block numbers. See [extractor.py](https://github.com/CLendering/SubspaceAD/blob/ef56d5c8ab2f1feb7dda1c93b25cc3f73f0960d7/src/subspacead/core/extractor.py). No per-patch unit normalization is applied by this aggregation. |
| Shots | Script runs k=1,2,4 with seed42. k counts original normal training images per category. `main.py` shuffles normal training paths and takes k; augmented views are not additional independent shots. |
| Support augmentation | `aug_count=30` means the original plus 30 generated views, totaling 31 views per base image when augmentation is enabled. Default `aug_list=['rotate']` uses `RandomRotation(degrees=(0,345))`. The default exception disables augmentation for `transistor`. See [main.py](https://github.com/CLendering/SubspaceAD/blob/ef56d5c8ab2f1feb7dda1c93b25cc3f73f0960d7/main.py), [transforms.py](https://github.com/CLendering/SubspaceAD/blob/ef56d5c8ab2f1feb7dda1c93b25cc3f73f0960d7/src/subspacead/data/transforms.py), and [config.py](https://github.com/CLendering/SubspaceAD/blob/ef56d5c8ab2f1feb7dda1c93b25cc3f73f0960d7/src/subspacead/config.py). |
| Preprocessing | Script enables no center crop, CLAHE, background mask, specular filter, or image patching. The feature extractor resizes to a square 672×672 input using its pretrained image processor. These optional CLI features must not silently enter the reference recipe. |
| PCA and patch scores | Unwhitened PCA retaining 99% explained variance; default score is squared Euclidean reconstruction residual, with `drop_k=0`. [pca.py](https://github.com/CLendering/SubspaceAD/blob/ef56d5c8ab2f1feb7dda1c93b25cc3f73f0960d7/src/subspacead/core/pca.py) uses a two-pass mean/covariance calculation in float64. |
| Maps and image score | [scoring.py](https://github.com/CLendering/SubspaceAD/blob/ef56d5c8ab2f1feb7dda1c93b25cc3f73f0960d7/src/subspacead/post_process/scoring.py) bilinearly resizes to the configured square resolution and applies a 3×3 Gaussian kernel with sigma4. The default image aggregation is the mean of `max(1,floor(0.01×number_of_pixels))` highest processed-map values. The script inherits this `mtop1p` default. |

The standalone CLI defaults differ from the benchmark script: it defaults to the register-equipped **large** model, resolution256, and no augmentation. The selected mean hidden-state indices and PCA/scoring defaults above remain declared in the CLI. A Phase B fidelity specification must name the recipe being reproduced rather than treating “official defaults” as unambiguous.

Two source caveats require explicit handling before a faithful baseline claim. First, the full-image feature generator constructs random augmentations anew on each invocation, while PCA invokes it separately for mean and covariance. Freezing the exact augmented realizations would be a reproducibility improvement but a declared implementation deviation. Second, the current publisher abstract and repository README report different summary numbers. For example, the publisher abstract reports one-shot MVTec image AUROC98.0%, while the README introductory figure reports97.1%. This review does not resolve that discrepancy and does not use either as a matched empirical target.

The existing project adapter imports the official PCA/scoring core but uses ViT-B/14, 224 pixels, declared blocks `(2,5,8,11)`, a raw mean of those blocks, and no support augmentation. That is a common-backbone scoring-core adaptation, not reproduction of the published giant/registers, 672-pixel augmented benchmark.

## VisionAD research method: exact inspected recipe and blockers

Current upstream HEAD was verified as [`2d5e36f357409125ccd9646ba016824005599df4`](https://github.com/Qiqigeww/VisionAD/commit/2d5e36f357409125ccd9646ba016824005599df4). Its paper abstract identifies four components: a vision foundation model, support and query augmentation, multilayer integration, and class-aware memory for multiclass detection. The class-separated code below does not by itself establish a faithful reproduction of that multiclass setting.

| Item | Verified class-separated code setting |
|---|---|
| Backbone | `dinov2reg_vit_large_14`, a DINOv2 ViT-L/14 model with four register tokens. See [dade_mvtec_test.py](https://github.com/Qiqigeww/VisionAD/blob/2d5e36f357409125ccd9646ba016824005599df4/dade_mvtec_test.py) and the analogous [VisA script](https://github.com/Qiqigeww/VisionAD/blob/2d5e36f357409125ccd9646ba016824005599df4/dade_visa_test.py). |
| Spatial transforms | Resize to448×448 then center-crop392×392; ImageNet normalization. See [dataset.py](https://github.com/Qiqigeww/VisionAD/blob/2d5e36f357409125ccd9646ba016824005599df4/dataset.py). |
| Features and scoring | Zero-based transformer blocks4 through18 inclusive are arithmetically averaged. CLS/register tokens are removed; each support and query patch descriptor is unit normalized. DADE returns `min_support_patch(1−cosine_similarity)` at each query patch. See [models/uad.py](https://github.com/Qiqigeww/VisionAD/blob/2d5e36f357409125ccd9646ba016824005599df4/models/uad.py), class `DADE`. |
| Base support set | One randomly shuffled normal-training batch of `args.shots`, with default shots1 and seed1. Shots refer to original images, not augmented descriptors. |
| Support views | `rotate_supports=True` produces six views: identity, 90/180/270-degree rotation, vertical flip, horizontal flip. Views are pooled into the memory for patch search. |
| Paired query/support views | The advertised scripts call `evaluation_batch_vis`: original tensors; a vertical flip of both queries and supports, whose predicted map is flipped back; and a `clamp(min=0)` of the already ImageNet-normalized query/support tensors. These are three separate memory slots. Their maps are **summed**. The function named `color_jitter_batch` implements the flip in this revision; its color adjustments are commented out. |
| Image aggregation | The combined patch map is bilinearly interpolated to256×256; the score is the mean of its highest floor1% values. Evaluation masks are resized to256×256. This differs from the project's native-resolution evaluation and must be documented in any comparison. |

**Numerical-evaluation blocker:** at the verified commit, the [advertised scripts](https://github.com/Qiqigeww/VisionAD/blob/2d5e36f357409125ccd9646ba016824005599df4/dade_mvtec_test.py) invoke [utils.py, `evaluation_batch_vis`](https://github.com/Qiqigeww/VisionAD/blob/2d5e36f357409125ccd9646ba016824005599df4/utils.py#L380). In that function, numerical AUROC/AP/F1/AU-PRO computations are commented out and their return values are set to zero; it saves visualizations. A controlled Phase B wrapper must export raw predictions and compute real metrics independently. Calling the script successfully would not substantiate reported accuracy.

**Licensing blocker:** GitHub metadata has `license:null`; the license endpoint returns404; the complete recursive tree was inspected and has no recognizable LICENSE/COPYING file. This establishes an unresolved code license, not permission to redistribute its source. Phase A can cite the method and describe its mathematics. A future implementation can independently implement its mathematical ideas; distributing or adapting upstream code requires resolving the upstream terms first. This report does not require a user approval request or copy that source into the code bundle.

The original requirements target Python3.8 and torch1.12/CUDA11.3 with old numeric dependencies. They cannot be installed verbatim into the current Python3.12 environment. Using the existing frozen ViT-B/14 checkpoint, zero-based blocks such as `(2,5,8,11)`, 224-pixel aspect-preserving transforms, and selectively enabled safe augmentations would be an explicitly modified research component, not the original large/registers recipe. Right-angle rotations can invalidate orientation-sensitive inspection tasks; their benefit should be tested by predeclared ablation rather than assumed.

Published performance numbers above are deliberately not used as evidence for this project's accuracy. Backbone size, full-shot versus few-shot data, crop handling, support IDs, augmentations, category splits, masks, and metric definitions must be paired before such a comparison is meaningful.

For uncertainty and selective inspection, three verified primary sources constrain what can be claimed:

- [A Gentle Introduction to Conformal Prediction and Distribution-Free Uncertainty Quantification](https://arxiv.org/abs/2107.07511) explains calibration and uncertainty sets. Its page links the authors' [conformal-prediction examples](https://github.com/aangelopoulos/conformal-prediction). Distribution-free does not remove the need for the applicable exchangeability/sampling assumptions. The project's diagnostic adequacy sigmoid is not a calibrated probability or an uncertainty set.
- [Testing for Outliers with Conformal p-values](https://arxiv.org/abs/2104.08279) studies reference-distribution outlier tests and the dependence of multiple conformal p-values. Any future calibration claim must identify the sampling unit, the independent/reference data assumptions, and the actual guarantee; correlated image patches cannot be treated as independent calibration images. A missing normal support mode can itself violate the representativeness needed for deployment interpretation.
- [SelectiveNet: A Deep Neural Network with an Integrated Reject Option](https://arxiv.org/abs/1901.09192) explicitly optimizes prediction and rejection and evaluates risk versus coverage. Merely rejecting more inspections is not an accuracy improvement: report coverage together with conditional error, missed defects, and reference-acquisition cost. Its published classifier recipe is not implemented here and is not an anomaly-localization baseline.

PatchCore's coreset concerns **patch-memory compression**; VisionAD's support augmentation concerns **views of the same normal exemplars**. Neither is equivalent to choosing additional independent reference images to repair a missing normal mode. Those must be accounted for separately in support budgets and acquisition experiments. The review found no basis for labeling the existing source-trained benefit regressor a published algorithm or for claiming its synthetic-source improvements generalize to native industrial defects.

## Narrow novelty assessment and design implications

The searches recorded in the evidence JSON were bounded GitHub repository/code queries for `VisionAD`, `SubspaceAD VisionAD`, the exact string `SubspaceAD-VisionAD`, `"support adequacy" anomaly`, `"subspace" "nearest neighbor" anomaly`, and PaDiM official-code identification. Exact hybrid/name queries returned no matches. These searches mostly inspect names, descriptions, or indexed code and cannot exclude related work expressed differently. The attempted OpenAlex academic searches were blocked by HTTP403, so no academic absence conclusion is valid. Relevant papers were therefore checked directly through their authoritative arXiv/CVF pages, plus official source references.

Combining pretrained features, PCA, nearest-neighbor distance, augmentation, calibration, rejection, or reference selection is not by itself established novelty. A defensible research hypothesis for a later phase is narrower: **whether separate global normal-variation modeling and local support coverage, calibrated using normal training images and evaluated under controlled support omissions, improve reliable localization without introducing missed defects**. This is a question to test, not a claimed contribution or result.

There is a concrete issue in the existing normalized-descriptor max hybrid. Orthogonal projection cannot increase a vector norm; therefore `||P_perp(q−nearest_support)|| ≤ ||q−nearest_support||`. Taking the maximum of those two signals makes that orthogonal-nearest component redundant. A global residual can add a different signal, but it is also strongly related to the nearest distance plus the support's own residual. This algebra does not establish that PCA is useless; it identifies why adding a component name need not produce new evidence.

A later experimental design could pair **raw multilayer-mean PCA reconstruction** with **normalized patch-search distance**, preserving feature-magnitude and subspace information in the former while using local feature matching in the latter. Their incompatible units must be normalized using disjoint normal training calibration images and fixed support sets, without per-query or test-set min/max scaling. Calibrated max, arithmetic fusion, and component-only ablations should be prespecified. A max of separately threshold-normalized image scores can preserve each component's alert under its fixed threshold, but it can increase normal false positives; threshold recalibration or pixel-map averaging can also lose that property. No fusion guarantees improved image/pixel ranking or fewer missed defects.

Phase A ends with this literature/source review and the accompanying audit and implementation plan. Phase B would first resolve reference-recipe, license, input transformation, source-version, metric-export, and data-split contracts before any new implementation or experiment. Earlier validation categories have already been inspected; they cannot be relabeled as untouched final test categories. The previously observed missed-defect events remain evidence against the earlier acquisition configuration and must not disappear from the historical report when a new hybrid is proposed.
