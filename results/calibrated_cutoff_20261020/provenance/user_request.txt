MODEL
This is an experimental SAFAL hybrid, not an LLM or an official paper reproduction:

- Frozen DINOv2 ViT-L/14 with register tokens.
- Normal support images provide patch-feature reference banks.
- Baseline: nearest-normal-patch cosine-distance scoring.
- Hybrid: baseline plus the existing normalized PCA-residual correction.
- Global PCA retains 95% variance.
- The existing controlled protocol selected lambda=0.25.
- Full-field input: resize=448, crop=448.
- Image score: mean of the highest-scoring 1% of map pixels.
- There is no gradient training, optimizer or epoch loop.

Read protocol.json and the frozen implementation before changing anything.
Verify the recorded settings rather than relying on this description.
Preserve the exact feature aggregation, layers, augmentation, normalization,
PCA fitting, fusion and image-score definitions. Do not silently simplify them.

CUTOFF RULES
Evaluate these rules for each scoring method:

A. AD2 fixed cutoff:
   Preserve the existing source-calibrated control. Document exactly which
   cutoff applies to each support budget and do not refit it on VisA.

B. Support leave-one-out percentile:
   Applicable only for k>=2. Fit on k-1 support images and score the held-out
   normal support image. Derive the cutoff from these held-out scores.
   Document the percentile definition and the small calibration sample size.
   Do not claim a guaranteed 5% false-alarm rate from two or four observations.

C. Support-statistics normalization:
   Derive category/bank-specific location and scale from normal support patch
   scores, using z-score or median/MAD normalization.
   Fit the final normalized-score threshold on AD2 source data only.
   Prevent trivial self-matching from producing misleading zero-scale statistics.
   Any patch cross-fitting, self-match exclusion, scale floor and normalization
   choice must be specified, tested and frozen using source data only.
   Never estimate normalization statistics from target query scores.

D. Oracle diagnostic:
   Report a target-label-dependent cutoff separately, labelled:
   “UNATTAINABLE ORACLE — uses target labels”.
   Compute it only after predictions are fixed. It must not influence selection,
   deployable cutoffs, settings or the success verdict.
